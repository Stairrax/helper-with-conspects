# Стабилизация после аудита

Приоритет: загрузить материал без потерь, подготовить проверяемый конспект, диктовать с остановкой и продолжением. Новые провайдеры и дополнительные функции не являются частью этой работы.

## Что изменено

- PDF оценивается постранично. Страницы с текстом сохраняются, страницы с недостаточным текстовым слоем рендерятся для OCR; результаты объединяются в исходном порядке. Ограничение 20 применяется к числу страниц для OCR.
- После MAX_TOKENS фрагмент всегда уменьшается. Не более 16 разбиений на тему; фрагменты короче 200 символов не дробятся дальше.
- Автопроверка хранит passed / failed / partial / not_checked. Пустой список пунктов, ошибка или неполный ответ проверки не дают зелёную отметку. Дополненный текст требует сверки: успешная генерация дополнений сама по себе не является проверкой.
- Кэш OCR учитывает провайдера, адрес, запрошенную модель, запасные модели, язык, версию обработки и ручной сброс. «Распознать заново» сбрасывает весь выбранный источник; действие выполняется при следующем составлении плана. В автоматическом серверном маршруте фактически выбранная версия модели может меняться без смены идентификатора auto — при сомнении используйте ручной сброс.
- OpenAI требует DONE, Gemini — STOP, Anthropic — message_stop. Обрыв, повреждённый JSON, ограничение длины и отмена не считаются успехом. Полученный частичный ответ сохраняется с предупреждением.
- Gemini и Anthropic имеют общий срок операции, включая ожидание сети и задержки повторов; отмена прерывает ожидание.
- Публичный health не вызывает модель. Рабочие запросы идут через квоты; Workers AI может работать без ключа OpenRouter. Размер тела ограничивается по фактически прочитанным байтам.
- JSON-копии не содержат активный ключ, ключи профилей и устаревший cloudKey. Внутренний снимок для отката восстановления остаётся полным, чтобы не потерять настройки при ошибке.
- Для исполняемых библиотек PDF.js/Mammoth закреплены версии и SHA-384 SRI. Изменённый файл CDN не должен выполняться в основном окне.
- Для вопроса по большому материалу выбираются фрагменты по словам вопроса из всего документа, а не только начало. Это простой поиск, не семантический поиск и не гарантия релевантности.

## Проверки

Основной набор: npm test. Новые сценарии: tests/33-audit.test.mjs.
Отдельная интеграционная проверка: node tests/pdf-integration.mjs (нужен доступ к CDN). Она использует настоящий PDF.js и оригинальный синтетический PDF из tests/fixtures/mixed-study.pdf.base64. На странице 2 текст нарисован в изображении, страницы 1 и 3 имеют текстовый слой.

Эталон PDF:
1. F = ma; масса 2 kg, ускорение 3 m/s2, сила 6 N.
2. E = mc^2; температура -5 C, изменение +2 C.
3. Вклад 1000, ставка 5%, через год 1050; дата 2026-11-10.

Интеграционный тест подтверждает сохранение/маршрутизацию страниц, **не качество распознавания нейросетью**. Искусственные сетевые ответы нужны для воспроизводимых тестов ошибок, а не для измерения качества модели.

## Как проверять качество учебного содержания

Для первичного анализа добавлены [ручная методика и фикстуры](quality.md), автоматическая проверка маркеров фактов и формул без API-ключей и дополнительные браузерные сценарии PDF. **Маркеры не являются оценкой точности ИИ**: проверяющий сверяет каждое утверждение с первоисточником. Реальную модель и платные сервисы тесты CI не вызывают.

## Что остаётся проверить и улучшить

- Реальные фото тетрадей, смешанные страницы с текстом и диаграммами, сканы с ошибочным непустым OCR-слоем, таблицы и формулы. Порог длины текстового слоя не обнаруживает все случаи повреждений.
- Набор учебных материалов с разрешением на использование и человеческими эталонами. Для каждой модели фиксировать исходник, результат, пропущенные факты, искажения чисел/единиц/формул, токены, запросы, время и стоимость. Отдельно проверять русский и английский. Сверка должна выполняться человеком; совпадение JSON-формата ничего не доказывает.
- Реальный iOS Safari и настоящие микрофоны/голоса: автоматическая эмуляция не заменяет устройство.
- Полная локальная поставка всех исполняемых зависимостей, включая PDF worker, ONNX и Piper, и CSP с проверкой голосов/пользовательских API. SRI основного PDF/DOCX-скрипта — частичная защита, не закрытие всей цепочки поставки.
- Парольный зашифрованный перенос секретов не реализован; ключи вводятся отдельно после восстановления.
- Административная активная диагностика не добавлялась: публичный опасный путь удалён, проверка публикации использует обычный ограниченный маршрут.
- Аутентификация и защита от автоматизации для массового сервиса. Origin и случайный ID устройства не доказывают личность. Квота провайдера общая, резервный сервер с тем же ключом её не увеличивает.
- Подбор контекста по токенному бюджету конкретной модели вместо консервативного символьного бюджета.
- Коммерческое использование голосовых моделей требует отдельной проверки их лицензий. Лицензии и сами голоса этой правкой не изменялись.

PR резервного сервера не объединяется автоматически в рамках этой работы.
