# Оценка качества конспектов

Этот раздел предназначен для проверки **содержания**, а не для демонстрации того, что нейросеть возвращает корректный JSON.

## Набор проверочных материалов

`tests/quality/cases.json` содержит четыре оригинальных синтетических примера по физике, финансам, биологии и химии (русский и английский). Для каждого указаны исходный текст и пункты ручной проверки: формулы, числа, единицы измерения, отрицания и смысловые связи.

## Как проверять

1. `npm run quality:list` — получить список примеров.
2. `node tests/quality/evaluate.mjs --case physics-ru --show-source` — прочесть текст. Загрузить **именно этот** исходник в приложение.
3. Записать провайдера, фактически выбранную модель, режим проверки полноты, дату, число запросов, время, токены и стоимость (если известно).
4. Составить план, подготовить куски для диктовки, экспортировать результат в Markdown и сохранить его как `answer.md`.
5. `node tests/quality/evaluate.mjs --case physics-ru --answer answer.md --report physics-review.json` — получить черновик для ревью.

В отчёте обязательно заполнить `humanVerdict` для **каждого** пункта значением `correct`, `omitted`, `distorted` или `uncertain`, а причины записать в `humanNotes`. Отдельно перечислить все факты, которых **нет** в исходнике, и оценить пригодность отрывков для диктовки.

**Проверка маркеров не является оценкой точности.** `[marker]` значит лишь, что встретилась одна из буквальных формулировок. Она может находиться внутри неправильного высказывания. `[review]` не доказывает ошибку: модель могла корректно перефразировать. Даже при всех найденных маркерах нужна проверка человеком.

Вся автоматическая проверка работает **локально и без API-ключей**. Скрипт не отправляет материалы в сеть и не перезаписывает уже существующий отчёт. Настоящую нейросеть CI не запускает. `npm run test:quality` проверяет корректность фикстур и сам инструмент, а не качество модели.

## Что измерять по результатам ручного анализа

Считать отдельно: пропущенные существенные факты, изменённые числа/даты/единицы измерения, искажённые формулы, потерянные отрицания, недостоверные дополнительные утверждения, а также сбои распознавания OCR. Сравнивать разные модели следует на одинаковых исходниках и настройках; если сервер меняет модель автоматически, это необходимо отмечать.

Сейчас это **начальный, заведомо небольшой набор**, а не репрезентативный бенчмарк. Далее нужны законно используемые реальные страницы, таблицы, формулы, рукописные заметки и отдельные проверки русского и английского языков. Не сохранять личные материалы и API-ключи в открытый репозиторий.

PDF-маршрутизацию тестирует `npm test` с подменой PDF.js; реальный `node tests/pdf-integration.mjs` требует CDN и проверяет только чтение и распределение страниц, не качество OCR.
