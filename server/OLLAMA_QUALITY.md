# Локальный тест качества конспектов: Ollama 7B

Это **отдельный эксперимент** поверх чернового локального резервного сервера PR #13. Он использует настоящий код приложения для составления плана и подготовки кусков диктовки. Все запросы идут только в локальную Ollama через `127.0.0.1`; Cloudflare, OpenRouter и платные API не используются. Реальные студенческие данные сюда не добавляются.

## Один пример сначала

Установленная Qwen 2.5 7B уже подтвердила работу обычного ответа и потока. Для полноценного структурированного конспекта:

```bash
cd ~/helper-with-conspects
git fetch origin
git switch experiment/ollama-quality-7b
git pull --ff-only
MODEL_NAME=qwen2.5:7b npm run quality:ollama -- --case physics-ru
```

Если Node.js сообщает, что нет Playwright, выполните `npm ci` и `npx playwright install chromium`. Ollama должна быть запущена, а `ollama list` — показывать `qwen2.5:7b`.

Только после первого успешного теста можно запустить сразу все четыре примера:

```bash
MODEL_NAME=qwen2.5:7b npm run quality:ollama
```

Если JSON не соответствует формату, сеть прервалась или модель не успела ответить — тест должен честно завершиться ошибкой. Не нужно копировать результаты вручную или повторно вводить тексты: фикстуры `tests/quality/cases.json` загружаются автоматически.

## Результаты

Тест создаёт **локальную** папку `reports/quality-ollama/<дата-время>/`. Она добавлена в `.gitignore` и не отправляется в GitHub.

- `summary.json`: статус каждого примера, модель и число запросов.
- `physics-ru.md` и аналогичные файлы: **настоящий текст для диктовки**, полученный от Qwen через приложение, плюс выделенные формулы.
- `physics-ru.json`: структура тем, пунктов и кусков, статус генерации и ошибки.
- `physics-ru-review.json`: черновик проверки контрольных фактов, если генерация завершилась.

В каждом тесте отдельно запускается локальный API, поэтому потраченные на первый пример запросы не мешают следующему.

**Важно:** статус `generated` означает лишь, что приложение получило куски в ожидаемом формате. Он не означает, что текст точен. Совпадение контрольных слов или чисел — механический маркер, не подтверждение достоверности. Итоговый разбор должен проверить пропуски, отрицания, формулы, неподтверждённые факты и искажения смысла.

Для быстрого и недорогого первого опыта используется `coverageCheck: false` и `formulasApart: false`. Это не тест всех настроек приложения; OCR и диктовка голосом тоже не входят в текущий прогон. Локальная лаборатория в этом режиме явно разрешает до 1536 выходных токенов и повышенный лимит запросов на один пример; её обычные значения остаются прежними.

Если модель медленно отвечает, возможно завершение по тайм-ауту браузерного клиента. Не превращайте это в «успешный конспект»: сохраните отчёт и рассмотрим отдельно. Облачных расходов не возникает.
