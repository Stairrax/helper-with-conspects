- Этот статус фиксирует **наличие исправлений в исходниках**, а не гарантию отсутствия любых новых дефектов.

- GPL-лицензия исходного кода **не отменяет** ограничений сторонней модели Silero и других зависимостей. Перед коммерческой дистрибуцией полной сборки лицензии и состав компонентов необходимо проверить отдельно.

## Нагрузка и честные ограничения бесплатного режима — 12.11.2026

Проверка по актуальному коду (исправления — в PR `fix/usage-quota-srs-ux-2026-11-12`):

| Пункт | Решение |
| --- | --- |
| **1. Расход на большие конспекты** | Вместо оценки одного плана показана приблизительная стоимость всей подготовки: план, генерация, независимая проверка полноты, возможные дополнения и неизвестная стоимость ещё не распознанных фото. Проверка по умолчанию **не** выключена: безопасность содержания важнее экономии. `DAILY_NOTES=100` и `DAILY_TOTAL=900` не увеличивали: эти ограничения не гарантируют наличие бесплатной квоты у провайдера. Готовые темы сохраняются, остальные готовятся по мере чтения и могут продолжиться в другой день. **Большой материал по-прежнему может не завершиться за сутки.** |
| **2. Пиковая очередь SRS** | Первый успешный интервал рандомизирован (уверенный ответ: 2–3 дня; угаданный — короче). Расписание хранится **по темам**, а не отдельно по каждому вопросу. |
| **3. Восстановление leech** | Уже исправлено ранее: `recentLapses` позволяет выйти из `leech` после трёх уверенных правильных ответов; общий `lapses` сохраняется. |
| **4. Лимиты вывода Gemini и Anthropic** | Gemini получает 8192 токена вывода по умолчанию; Anthropic — тоже 8192 вместо прежних 16000/32000. Явное положительное `maxOutputTokens` учитывается в обоих клиентах. `Gemini.listModels` теперь ограничен общим 30-секундным дедлайном с отменой сетевого запроса. |
| **5. Дедлайн** | Для обычных запросов `notes` через бесплатный OpenAI-совместимый прокси — 180 с вместо 120 с; явный `timeoutMs` по-прежнему имеет приоритет. Gemini и Anthropic уже имели 180 с. Большее время не увеличивает квоту провайдера. |

### Цитаты объединённых тем

Исправлено преобразование секций в цитаты для тем, склеенных через `r.continues` из нескольких проходов плана. `generateTopicChunks` больше **не** ищет повторно `topic.text.indexOf(sectionText, sourceOffset)`: `sectionSpans` разбивает исходный текст с сохранением абсолютных диапазонов. Формулы и ключевые пункты получают смещения, рассчитанные непосредственно по оригиналу, включая случаи разделения по `MAX_TOKENS`. Переводы строк CRLF, неразрывные пробелы и повторы текста покрыты тестом `tests/45-continued-topic-citation-spans.test.mjs`.

**Непроверенное / отложенное:** реальная точность OCR на плохих фотографиях и рукописных страницах, реальное качество полноты конспекта, фактические квоты бесплатных моделей и доступность сервера из разных сетей. Для этого нужны испытания с реальными материалами, а не только заглушки ответов ИИ.

## Потеря текста при разбиении длинных абзацев — 12.11.2026

Исправлен старый дефект `splitSentences()`, существовавший **до** изменений по цитатам. Глобальное регулярное выражение могло пропускать знаки препинания при необычных сочетаниях кавычек, многоточий и смежной пунктуации. Теперь разбиение проходит исходную строку последовательно и сохраняет **все символы**, в том числе разделители и пробелы на границах блоков. Для длинных предложений без границ предусмотрено безопасное разрезание по длине без выбрасывания текста.

В `sectionSpans()` добавлена обязательная проверка: промежутки между секциями и вокруг них могут содержать только пробельные символы; пропуск непробельного символа приводит к явной ошибке вместо тихой потери учебного материала. В тесте `45-continued-topic-citation-spans.test.mjs` отдельно проверяются длинный абзац с закрывающей кавычкой, цепочка знаков препинания и длинное предложение без пунктуации. Для каждого проверяется полнота как плана, так и секций с точными цитатными смещениями.
